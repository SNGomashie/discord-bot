# Ralph progress log — started 2026-10-10 (feature: cs2-scoreboard; patterns carried over)

## Codebase Patterns
- Config: optional env ints go through `_parse_positive_int(source, key, default)` (or `_parse_optional_positive_int(source, key)` for values without a default, e.g. channel IDs) in config.py (raises ConfigError naming the variable). New Config fields need a default so existing constructors keep working.
- yt-dlp has no type stubs; mypy override for `yt_dlp` / `yt_dlp.*` is in pyproject.toml.
- Media errors: subclass MediaError and set `default_message`; `.message` is the user-facing text (safe to send to Discord).
- DownloadPlan: mp3 plans set `audio_bitrate_kbps`, mp4 plans set `height_ladder`; `format_selector(plan, height)` only accepts mp4 plans. Size filters use `<=?` so formats with unknown size still match — the downloader must check the real file size. Clipped plans get no size filter at all (yt-dlp filesize is for the whole video).
- Downloader: YtDlpDownloader takes injectable `extract`/`run`/`is_ytdlp_error` callables; tests pass stubs so yt_dlp is never called. Only downloader.py imports yt_dlp (lazily, inside the default callables).
- ruff ASYNC240 flags pathlib calls (iterdir etc.) inside async functions, including tests — put them in small sync helpers.
- Cog tests: call `Cog.command.callback(cog, interaction, ...)` or a plain `handle_*` method with a MagicMock interaction (AsyncMock for response.defer/send_message and followup.send). Command params/choices are inspectable via `Cog.command._params[name]`.
- /download cooldown is `UserCooldown` (media/cooldown.py, injectable clock) on the cog instance, not an app_commands check: `handle_download` takes it after URL/clip validation and refunds in a `finally` unless `_download_deferred` returns True (file posted). Tests inject `Media(downloader, 3600, UserCooldown(30, FakeClock()))`.
- ffmpeg is installed in Dockerfile.dev (rebuild the container to get it); prod LXC needs `apt install ffmpeg`.
- Clip times: `media/clip.py` parses/format timestamps; `InvalidClipError` messages are user-facing. `format_timestamp` (float, tenths) vs `format_duration` (int, models.py).
- plan_download with a clip: `plan.clip` is always resolved (concrete `end_s`); size estimates use `math.ceil(clip length)` since `estimated_size_bytes` takes int seconds.
- Clipped downloads: `build_ydl_options` adds `download_ranges` (yt_dlp.utils.download_range_func, imported lazily via `_download_ranges`) + `force_keyframes_at_cuts` only when `plan.clip` is set; it raises ValueError for an unresolved clip. The range callable can be invoked in tests as `fn({"duration": n}, None)` without network.
- Cog clip flow: `handle_download(interaction, url, kind, start=None, end=None)` parses URL and clip in one try block before defer (ephemeral on MediaError); `plan_download(..., clip=clip)` errors go through the followup MediaError path; success embed uses `plan.clip`, error embeds never show a clip. Param descriptions are `locale_str` — use `str(param.description)` in tests.
- Timestamp input: `MAX_TIMESTAMP_LENGTH` (clip.py) caps input before int()/float() and is the `app_commands.Range[str, 0, N]` max on start/end. Clip regexes use re.ASCII so Unicode digits are rejected. Range params expose the bound via `param.to_dict()["max_length"]` (CommandParameter stores it as `max_value`).
- Durations: `VideoInfo.duration_s` (int, truncated) is for display and the whole-video cap; `duration_exact_s` (float | None) is for clip resolution. `_opt_float` in models.py rejects bools/NaN/inf/overflowing ints; `_opt_int` builds on it.
- mp4 ladder: `height_ladder(info.video_heights)` in planning.py maps HEIGHT_LADDER rungs to the largest available height <= rung, deduped; `()` heights = full HEIGHT_LADDER. `VideoInfo.video_heights` comes from `formats[*].height` where vcodec != "none".
- mp4 options always include `FFmpegVideoRemuxer` (`preferedformat: "mp4"`, yt-dlp's spelling). If no `.{kind}` file appears but other new media files (`_MEDIA_SUFFIXES`) do, `download` logs them and raises DownloadError naming the wrong extension; `.part` files don't count.
- /download queue: `_wait_for_slot` edits the original response to QUEUED_MESSAGE when the semaphore is held and waits up to `QUEUE_TIMEOUT_SECONDS` (module constant; tests monkeypatch `ninja_bot.cogs.media.QUEUE_TIMEOUT_SECONDS`). handle_download releases the semaphore itself (no `async with`). Every send/edit on the deferred path goes through `_send_safely` (logs + swallows discord.HTTPException, returns success). Fake interactions need `edit_original_response = AsyncMock()`.
- Disk work stays off the event loop: `_download_deferred` uses `asyncio.to_thread(tempfile.mkdtemp)` + `to_thread(shutil.rmtree, ignore_errors=True)` in `finally`; downloader filesystem helpers (`_snapshot`, `_find_output`, `_file_size`, `_remove_new_files`, `_unexpected_suffixes`) are sync and called via `to_thread`. Tests verify by monkeypatching `asyncio.to_thread` with a recorder (`ThreadRecorder` in test_media_cog.py).
- YouTube extraction needs deno + yt-dlp-ejs (`yt-dlp[default]`); both are in the dev image. Tests never touch the network, so this only matters for manual runs.
- CS2 feature (tasks/prd-cs2-scoreboard.md): Leetify fixtures in tests/fixtures/leetify/ are hand-written from the public swagger (https://api-public.cs-prod.leetify.com/swagger.json), not captured from the real API; field names/units are unverified until scripts/capture_leetify.py is run by the owner. Never read .env or print LEETIFY_API_KEY.
- CS2 models (cs2/models.py): `Cs2Error` mirrors `MediaError` (default_message/.message). `PlayerMatchStats` has every stat optional except steam64_id (keyword defaults); `accuracy`/`spray_accuracy` are percentages (0-100). `hs_percent` is 0-100, `kd_ratio` with 0 deaths = kills. `Match.team_scores` is a tuple of `TeamScore(team_number, score)`; `Match.teams()` always returns 2 tuples (padded with `()`), dropping players without a team number. `Profile` ratings are flat fields; ranks live in `Ranks(premier, faceit_level, leetify)`; `RecentMatch.score` is (own, other).
- CS2 parsing (cs2/models.py): tolerant helpers `_opt_str`/`_opt_id`/`_opt_int`/`_opt_float` are duplicated from media/models.py (private there). `_percent` turns fractions <= 1.0 into 0-100 (accuracy, accuracy_head, spray_accuracy); `_milliseconds` turns match `reaction_time` < 10 (seconds) into ms. Both are guesses at units until the capture script is run. `_opt_datetime` parses ISO 8601 (incl. `Z`) and makes naive values UTC. Match stat names used: `trade_kills_succeed`, `flash_assist`, `initial_team_number`, `shots_hit_friend`. `team_scores` come out sorted by team number.
- CS2 profile parsing: `parse_profile` raises PrivateProfileError for any `privacy_mode` other than "public" (missing/null = public), ApiError without steam64_id. Faceit level comes from `ranks.faceit` (not `faceit_level`). `rating` holds aim/positioning/utility/clutch/opening/ct_leetify/t_leetify. Recent matches: entries without id are skipped, `outcome` outside win/loss/tie -> None, `score` must be a 2-item list; sorted newest first by finished_at (undated last, stable).
- CS2 Steam IDs: `parse_steam_id` (cs2/steam.py) caps input at `MAX_STEAM_INPUT_LENGTH` (200, raw text before strip) — reuse it as the `app_commands.Range` max on `/link steam`. Vanity URLs raise `InvalidSteamIdError(VANITY_URL_MESSAGE)`; everything else uses the default message. Host match is case-insensitive; query strings/extra path segments are rejected.
- CS2 client (cs2/client.py): `LeetifyClient(api_key, base_url, fetch, timeout_s)`; `fetch(url, headers) -> FetchResponse(status, body)` is injectable (tests use a `StubFetch`), default is a lazy aiohttp session closed by `aclose()`. `asyncio.timeout` wraps every fetch, so injected fetches are bounded too. Errors are raised `from None` with default messages and logs only show the path/status, so the key can't leak. `/v3/profile/matches` is expected to return a JSON list of match details (parsed with `parse_match`, bad entries skipped, newest first); unverified until the capture script runs.
